The key is stored in a cookie scoped to /v1 for eight hours, so the docs pages and their “try it” calls can use it without asking again.

Where does this key come from?

It is not an account and there is nothing to sign up for. The key is one of the comma-separated values in BARQR_API_KEYS, the environment variable whoever started this container chose. If that was you, it is in your run command: 

docker run --rm -p 8080:8080 \
  -e BARQR_API_KEYS=dev-key \
  barqr

With that command the key is dev-key. If barqr runs under compose or Kubernetes, look for BARQR_API_KEYS in the manifest or in the secret it references. Any one of the listed keys works. Setting BARQR_AUTH_MODE=open instead disables authentication altogether — reasonable on a laptop, not on a shared network.

No key is needed for /v1/healthz, /v1/readyz or /v1/version — a probe cannot hold one — nor for the landing page, which is why you can still read that one.
